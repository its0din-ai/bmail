## Decisions & notes

- **Public, self-hosted project.** No domain, email address, account ID, zone ID, or token is committed. Source, docs, tests, and `.env.example` use reserved examples only. Runtime config comes from `.env`; a missing or empty `bmail_mail_domains` fails closed (mail rejected, API returns a config error).
- **Implementation stack.** Worker: TypeScript, native `fetch` router, zero runtime dependencies, bundled by Wrangler. Client: TypeScript, `postal-mime`, `@modelcontextprotocol/sdk`, `zod`, built with `tsc`. Root tooling: pnpm workspace, Vitest.
- **Multi-domain from day one.** `bmail_mail_domains` is a comma-separated `domain:mode` list. `catch_all` means every local part reaches the Worker and new aliases are allowed. `fixed` means only addresses in `bmail_fixed_addresses` are accepted and no new aliases can be created. Each alias is keyed by `(mail_domain, local_part)` and every message stores its `mail_domain`. A request that names an unconfigured domain is rejected.
- **`mail_domain` parameter.** Optional on every API list/create route, every MCP tool, and every CLI command. When omitted, the server uses `bmail_default_mail_domain`. If neither is set, the API returns a clear error instead of guessing.
- **Two ingress shapes, one app model.** A `catch_all` domain has an Email Routing catch-all and dynamic aliases. A `fixed` domain has a literal rule for one address, typically a program mailbox on a second owned domain, and its alias is auto-created on first inbound from `bmail_fixed_addresses`. Both end up as a normal alias row.
- **Tokens.** Format `bmail_<id>_<64 hex chars>`. Stored as `sha256(pepper + ":" + secret)`; compared in constant time; scoped per domain; optional expiry. The operator token `bmail_admin_token` is env-only and guards `POST/GET /v1/tokens` and `DELETE /v1/tokens/:id`.
- **Duplicate delivery guard.** `messages.message_id` has a partial unique index. A duplicate Message-ID is dropped, its R2 object deleted, and no mirror copy is sent.
- **Zero-parse Worker.** `email()` does alias lookup, header capture, raw stream to R2, one D1 insert, and the mirror `forward()`. It never parses MIME. Raw mail stays in R2 and is parsed by the `bmail` client on the agent host. This keeps ingest inside the 10 ms CPU budget and keeps untrusted content out of the Worker.
- **Mirror loop guard.** `bmail_forward_to` must not be on a configured mail domain. Ingest drops any message that already carries `X-BMail-*` headers, so a misconfigured mirror cannot loop and burn the free quota.
- **Retention.** `bmail_retention_days`, default 90. Cron deletes messages older than the window and aliases older than the window only when they have no messages inside the window, so active aliases survive. R2 lifecycle deletes raw objects. Expired tokens are deleted.
- **Error policy.** Unknown aliases and unknown domains are accepted and dropped without storage. If storage fails, the mirror is still attempted; if both fail, the error is rethrown so the platform can retry. Config errors drop mail and log the reason.
- **Configuration path.** `.env` is the source of truth. `scripts/dev.mjs` writes `worker/.dev.vars`; `scripts/deploy.mjs` generates a temporary Wrangler config with D1/R2 ids, deploys with `--var`, then sets secrets. `.env` stays gitignored.
- **Plan: Workers Free.** 100,000 requests/day; 10 ms CPU per HTTP request and per Cron Trigger; 128 MB memory; 50 subrequests; 5 Cron Triggers. D1: 5M rows read/day, 100,000 rows written/day, 5 GB. R2: 10 GB-month, 1M Class A and 10M Class B ops/month. No Durable Objects, no Queues.
- **Security profile: strict core + free-tier efficiency.** Hashed tokens, domain scope, optional expiry, sender authentication, input validation, secrets handling, and dependency audit. No rate limiting; the daily request cap is the backstop.
- **MCP runs next to the agent (stdio), not in the Worker.** The `bmail` package is installed on the agent host and calls the public HTTPS API. No Worker-side MCP, no OAuth, no Durable Objects.
- **No KV.** Aliases and messages live in D1; KV's 1,000 writes/day free limit is not worth a second store.
- **Polling is client-side.** `wait_for_message` loops in the MCP client with a `since` cursor and backoff.
- **Ingress delegation.** A domain must be an apex of a Cloudflare zone for catch-all. If the chosen mail domain is a subdomain, delegate it as its own zone first.
- **Local Email Routing test.** In this Wrangler version the local endpoint is `POST /cdn-cgi/handler/email` with `from` and `to` query parameters, not `/cdn-cgi/local/email`.
- **Compatibility date.** Set to `2026-03-12`, the maximum supported by the installed workerd. No newer runtime feature is used.
- 2026-11-16: design system overridden from Material 3 to **Neo Brutalism**, requested by the user, reference <https://www.neobrutalism.dev/docs>. Recorded in `INIT.md` per `AGENTIC.md` section 13. `AGENTIC.md` itself is unchanged because it is the static rulebook. Motion (anime.js) and light/dark/auto remain in force.
- 2026-11-16: v1 is inbound only. No `send_email` binding, no outbound table, no reply/send tools. `message.reply()` exists only inside the `email()` handler, so agent-authored replies would need Email Sending later - deferred.

## Free-plan feature budget

**Kept (each sized against the Free limits):**

| area | v1 behavior |
|---|---|
| Ingest | one request, one D1 write, one R2 Class A put, one mirror forward. No MIME parse. |
| Alias management | create, list, delete. `catch_all` only for new aliases; `fixed` auto-creates from the allowlist. |
| Read | list metadata, get metadata, stream raw. No body parse in the Worker. |
| Wait | client-side poll with a `since` cursor and backoff. |
| Auth | bearer token, SHA-256 with pepper, domain scope, optional expiry, admin token for token management. |
| Retention | one Cron Trigger per day plus an R2 lifecycle rule. |
| Client | one `bmail` package: CLI and stdio MCP. |

**Dropped as unneeded for v1:**

- attachments table and download endpoint (the raw MIME already contains them)
- read/unread state and `mark_read`
- threading (`thread_id`, `References`, `In-Reply-To`)
- per-alias token scope and alias ownership
- alias pause, update, kind, and status (delete and recreate instead)
- D1 audit log (Workers console logs instead)
- rate-limit tables and counters (unknown aliases are dropped; token auth and the daily cap remain)
- CORS (there is no browser client)
- HTML rendering and sanitization (the client works on text and raw)
- quota alerting (Cloudflare dashboard)

**Data model (v1):**

```
aliases(id, mail_domain, local_part, label, created_at)
  unique(mail_domain, local_part)
  index(mail_domain, created_at)

messages(id, alias_id, mail_domain, from_addr, to_addr, subject,
         message_id, dmarc, size, raw_r2_key, received_at)
  index(mail_domain, received_at), index(alias_id, received_at)
  unique(message_id) where message_id is not null

agent_tokens(id, name, token_hash, domains, expires_at, created_at)
```

**API surface (v1):**

- `GET /health`
- `GET /v1/config`
- `GET /v1/aliases`, `POST /v1/aliases`, `DELETE /v1/aliases/:id`
- `GET /v1/messages`, `GET /v1/messages/:id`, `GET /v1/messages/:id/raw`
- `POST /v1/tokens`, `GET /v1/tokens`, `DELETE /v1/tokens/:id` (admin token only)

**MCP tools (v1):** `config`, `list_aliases`, `create_alias`, `delete_alias`, `list_messages`, `get_message`, `wait_for_message`.

**Observability:** `console.log` for auth denials and errors, Cloudflare dashboard for usage. No D1 audit table, no body logging.
