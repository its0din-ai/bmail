## Decisions & notes

- **Flow.** Pick an address that matches the allowlist, for example `test@mail.example.com` or `bbounty@programs.example.net`. There is no registration and no alias table. The agent polls that address with the shared key.
- **Storage.** One R2 object per message at `mail/<address>/<id>.eml`, where `id` is `<13-digit ms>-<12 hex>`, plus one small latest marker per address at `latest/<address>`. The timestamp prefix makes lexicographic order chronological. Ack deletes the message object; a lifecycle rule expires both prefixes after `bmail_lifecycle_days`.
- **Metadata.** R2 custom metadata stores `from`, an ASCII-safe `subject` preview, `received_at`, `size`, and `dmarc`. The real subject and body are parsed from the raw message by your tool, so non-ASCII subjects are preserved there.
- **Paging.** `GET /v1/inbox/:address?after=<key>&limit=<n>` uses R2 `startAfter`; `next_cursor` is the last object key. Messages are ascending by id.
- **Latest marker.** Ingest writes `latest/<address>` with the last message key after writing the message. A cursor poll first does `head` on that marker: if the marker is not newer than `after`, it returns empty without `ListObjects`. This keeps polls on R2 Class B and saves Class A for actual new mail.
- **Polling cost.** One cursor poll with no new mail is one `head` (Class B). A poll that finds new mail is one `head` plus one `list` (Class A). The Worker imposes no polling interval; your tool should use backoff.
- **Raw access.** `GET /v1/inbox/:address/:id` streams the R2 object as `message/rfc822` with `x-bmail-*` metadata headers.
- **Auth.** One shared `bmail_api_key`, at least 16 characters, sent as `Authorization: Bearer`. Constant-time compare. The key grants access to every configured address. Health is unauthenticated.
- **Domains.** `bmail_mail_domains` is a comma-separated allowlist. An entry is either a domain (any local part) or a full address (exact). Addresses outside it return 403. Email Routing decides what reaches the Worker; this allowlist is the second gate.
- **Validation.** Local parts are restricted to `[a-z0-9._+-]` with no slashes, so an address cannot escape its R2 prefix. Message ids must match `<13 digits>-<12 lowercase alnum>`.
- **DMARC trust.** Follow the docs: read only the first `Authentication-Results` header, require `mx.cloudflare.net` as its authserv-id, then store its dmarc result. A sender-supplied header that merely mentions Cloudflare is ignored. Tested in `worker/test/index.test.ts`.
- **No bundled client.** The Worker exposes REST only. MCP, stdio, HTTP MCP, and the Node client were removed; add custom tools later against the REST API.
- **ARTEX custom tools.** `artex-custom-tools.json` defines three HTTP custom tools (`bmail_list_messages`, `bmail_get_message`, `bmail_ack_message`) with placeholders for the Worker URL and key. The user feeds it into the ARTEX chat; the auto agent creates them with `create_custom_tool`.
- **Deletion.** `DELETE /v1/inbox/:address/:id` deletes the `.eml` object and returns 204, including when the object is already gone. Your tool calls it directly. The latest marker may point at a deleted object; that is harmless because new mail updates it. The owner's forwarded archive is untouched.
- **Lifecycle.** `pnpm deploy:worker` sets an R2 lifecycle configuration with two rules: `mail/` and `latest/`, each deleting objects after `bmail_lifecycle_days` (default 7 days, `maxAge` in seconds). It uses `wrangler r2 bucket lifecycle set --file`, which replaces the bucket's lifecycle rules, so the bucket should be dedicated to bmail.
- **No D1, no cron, no Durable Objects, no Queues, no KV.** R2 only.
- **Free plan.** Ingest is two R2 Class A puts (message plus marker); listing is one list; raw reads are one get; ack is a free delete. The daily request cap and R2 free quota are the backstops.
- **Config path.** `.env` is the source of truth. `scripts/dev.mjs` writes `worker/.dev.vars`; `scripts/deploy.mjs` generates a temporary Wrangler config, deploys `bmail_mail_domains` as a var, and sets `bmail_api_key` as a secret.
- **R2 streaming.** Production R2 requires a known-length stream. Ingest wraps `message.raw` in `FixedLengthStream(message.rawSize)` and awaits both the pipe and the R2 put. Local R2 is more permissive, so a local smoke test can pass while production rejects an unknown-length stream.
- **Observability.** `worker/wrangler.jsonc` enables Workers Logs with `enabled: true`, `head_sampling_rate: 1`, and `logs.enabled`, `logs.invocation_logs`, `logs.persist`. Workers Free includes 200,000 log events/day and 3-day retention. Custom logs contain the recipient, size, message id, and R2 error stacks; bmail never logs the message body or API key.
- **Local Email Routing test.** `POST /cdn-cgi/handler/email?from=...&to=...`.
- **Compatibility date.** `2026-03-12`, the maximum supported by the installed workerd. No newer runtime feature is used.
- 2026-11-16: design system overridden from Material 3 to **Neo Brutalism** for any future UI. v1 has no UI.
- 2026-11-16: outbound mail is out of scope. `message.reply()` only exists inside `email()`.
